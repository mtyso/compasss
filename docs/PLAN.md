# Компас — план первого этапа

Черновик на согласование, 21.10.2026. Концепция с макетами экранов: https://claude.ai/artifact/3T15ZdtSpgQ67sWwYpE4tt

Компас — личное приложение для денег, привычек и задач. Главная его работа не учёт, а **помощь в управлении деньгами**:
приложение каждый день считает, сколько можно потратить, предупреждает, где пора притормозить, и отвечает на вопрос
«можно ли мне это купить». Цели (второй этап) связывают деньги, привычки и задачи.

## 1. Решения

Решения пронумерованы, чтобы на них можно было ссылаться в коде и в обсуждениях. Если документ и код расходятся, правится то, что неверно, и решение здесь.

| № | Решение |
|---|---|
| D1 | Платформы: Android-приложение, веб и Telegram-бот. iPhone позже из того же кода, без переписывания. |
| D2 | Сервер: Laravel 13, PHP 8.4, MariaDB 11.4 на AHost (cPanel), как в emerich-dealers. Код без функций, специфичных для одной СУБД: локально можно MySQL 8.4 или SQLite. |
| D3 | Клиент: одна SPA на Vue 3 + TypeScript + Vite + Tailwind 4 + Vue Router + Pinia + vue-i18n. Веб открывает её в браузере, Capacitor собирает из неё Android-приложение. Inertia не используем: SPA должна работать внутри приложения без сервера страниц. |
| D4 | Монорепозиторий: `server/` (Laravel), `app/` (Vue + Capacitor), `deploy/` (скрипты выкладки), `docs/`. |
| D5 | Один поддомен на AHost: Laravel отдаёт `/api/*` и `/telegram/webhook`, все остальные адреса отдают собранную SPA (`server/public/index.html`). |
| D6 | Пользователь пока один, но у каждой записи есть `user_id`: семью можно подключить позже без переделки базы. Входить могут только Telegram-аккаунты из списка `ALLOWED_TELEGRAM_IDS` в `.env`. |
| D7 | Вход через Telegram-бота по одноразовой ссылке (раздел 6). В приложении поверх входа PIN из 4 цифр и отпечаток пальца, на вебе PIN. |
| D8 | Деньги храним целыми числами в минимальных единицах валюты: сум без тийинов, доллар в центах. У операции есть сумма в своей валюте и сумма в сумах по курсу на дату операции, итоги и бюджеты считаются в сумах. |
| D9 | Курсы валют: ЦБ Узбекистана (`cbu.uz`, JSON), раз в день по cron. Курс в операции можно поправить руками. Курсы и деньги считаем через `bcmath`, без float. |
| D10 | Языки: русский и узбекский (латиница) с первого дня. Стандартные категории переводятся по ключу, свои названия хранятся как ввёл пользователь. Код, таблицы, коммиты на английском. |
| D11 | Время: `Asia/Tashkent`, даты в интерфейсе `дд.мм.гггг`. |
| D12 | Фоновых процессов нет (ограничение AHost): один cron раз в минуту запускает `schedule:run`, очередь `database` разбирается из расписания с `--stop-when-empty`. Сессии и кэш в базе. |
| D13 | Выкладка как в emerich-dealers: `publish-release.ps1` на компьютере собирает ветку `release` (vendor без dev + собранная SPA), на сервере `deploy-git.sh`. |
| D14 | Операции, задачи, привычки удаляются мягко (soft delete). |
| D15 | Дни дохода задаются в настройках: один или несколько дней месяца с ожидаемой суммой. От ближайшего дня дохода считается дневной лимит. |
| D16 | Советник работает на правилах и расчётах, без ИИ. ИИ позже только объясняет и отвечает на вопросы, опираясь на те же посчитанные факты. |
| D17 | Платных сервисов нет. Firebase (пуш-уведомления) бесплатен; аккаунт Apple понадобится только для iPhone. |
| D18 | Тесты: Pest на сервере, Vitest на клиенте. CI в GitHub Actions гоняет тесты сервера на MariaDB 11.4, как на хостинге. |
| D19 | Операция всегда в валюте своего счёта: трата в долларах записывается со счёта в долларах. Обмен валюты — перевод между счетами, где указано, сколько пришло. Валюту счёта нельзя поменять после создания. |
| D20 | Курс на дату операции берётся из сохранённых курсов ЦБ; если его нет, сервер сразу спрашивает `cbu.uz`, а если ЦБ не отвечает — берёт последний известный курс. Если курса нет совсем, приложение просит ввести его вручную. |

## 2. Советник

Это сердце приложения. Советник смотрит на счета, операции, бюджет, дни дохода и регулярные платежи и делает три вещи:
говорит, сколько можно тратить, предупреждает заранее и честно отвечает, стоит ли покупать.

### 2.1. На чём он основан

- **Обязательные и гибкие траты.** Каждая категория расходов помечена: обязательная (аренда, коммуналка, продукты, лекарства) или гибкая (кафе, развлечения, одежда сверх нужного). Стандартный набор уже размечен, пометку можно поменять. Без этого советник не может сказать, «где можно, а где не нужно».
- **Разовые траты.** Операцию можно отметить как разовую (ремонт, подарок на свадьбу). Она входит в итоги, но не портит статистику «обычного» месяца.
- **Свободные деньги до дохода.** Главная величина:
  `свободно = деньги на счетах для трат − регулярные платежи до ближайшего дохода − запланированные взносы в накопления − неснижаемый остаток`.
  Сбережения и счета с пометкой «подушка» в «деньги для трат» не входят.
- **Дневной лимит** = свободно / дней до ближайшего дохода. Пересчитывается после каждой операции.
- **Темп категории**: доля потраченного бюджета против доли прошедшего месяца, и прогноз на конец месяца при текущем темпе.
- **Обычный уровень**: медиана трат по категории за последние 3 месяца, без разовых операций.

### 2.2. Что он подсказывает (первый этап)

| Правило | Когда срабатывает | Что говорит (пример) |
|---|---|---|
| Дневной лимит | всегда, на «Сегодня» и в утренней сводке | «Сегодня можно 90 000. До зарплаты 9 дней, обязательные платежи уже учтены.» |
| Темп категории | гибкая категория идёт заметно быстрее месяца | «Кафе: потрачено 70% бюджета, а месяц прошёл на 40%. Чтобы уложиться, не больше 25 000 в день.» |
| Прогноз перерасхода | прогноз на конец месяца выше бюджета | «При таком темпе на продукты уйдёт 2,9 млн при плане 2,5 млн.» |
| Порог бюджета | категория дошла до 80% и до 100% | «Подписки: 95% бюджета, осталось 10 000.» |
| Крупная трата | трата больше 2 обычных для категории | «Это заметно больше обычного для «Одежды». Отметить как разовую?» |
| Мелочи складываются | частые мелкие траты в гибкой категории | «Кофе 22 раза за месяц, это 660 000.» |
| Распределение дохода | в день дохода | «Пришла зарплата 12 млн. Обязательные платежи 4,2 млн, в подушку советую 1,2 млн, на жизнь остаётся 6,6 млн, это 220 000 в день.» |
| Подушка безопасности | раз в месяц и в день дохода | «Подушки хватит на 1,4 месяца обычных расходов. Цель 3 месяца: откладывай по 800 000.» |
| Норма сбережений | итоги месяца | «В октябре отложено 14% дохода, в сентябре было 9%.» |
| Хорошие новости | неделя без перерасхода, месяц лучше прошлого | «Неделя без перерасхода. В кафе на 180 000 меньше, чем в прошлом месяце.» |
| Не забыть записать | вечером, если за день нет ни одной операции | «Сегодня ничего не записано. Были траты?» |

Во втором этапе добавятся советы по целям («чтобы успеть к июлю, добавь 50 000 в месяц»), по долгам (что гасить первым),
поиск подписок среди повторяющихся платежей и связь привычек с экономией.

### 2.3. «Можно ли это купить?»

Вводишь сумму (и по желанию категорию), советник отвечает одним из четырёх вердиктов и объясняет почему:

1. **Можно** — укладывается в сегодняшний лимит.
2. **Можно, но** — укладывается в свободные деньги, но дневной лимит на оставшиеся дни станет меньше: «лимит станет 60 000 вместо 90 000 на 8 дней».
3. **Лучше подождать** — дневной лимит упадёт ниже обычных обязательных трат в день или бюджет категории будет превышен. Советник предлагает дату: «после зарплаты 10 ноября хватит без ущерба».
4. **Не стоит** — денег до дохода не хватит без подушки или накоплений: «придётся взять из подушки, она уменьшится до 0,9 месяца».

Работает в приложении (отдельная кнопка и подсказка прямо при вводе суммы в быстрой записи) и в боте: «можно купить наушники 600к?».

### 2.4. Где показывается

- **«Сегодня»**: дневной лимит и одна-две самые важные подсказки.
- **Быстрая запись**: пока вводишь сумму, внизу видно, как изменится лимит и бюджет категории.
- **Бюджет месяца**: на полосе каждой категории отметка «где надо быть сегодня» и прогноз.
- **Лента «Советы»**: история подсказок, можно отметить «полезно» или «не показывать такое».
- **Бот**: утренняя сводка (время в настройках), распределение дохода, предупреждения о бюджете, вечернее «не забыть записать», итоги недели в воскресенье.

### 2.5. Устройство

- Каждое правило — отдельный класс `App\Advisor\Rules\*` с методом `evaluate(AdvisorContext): ?Insight`. Правила чистые и детерминированные, поэтому легко тестируются на наборах операций.
- Правила запускаются по событиям: после сохранения операции, по расписанию (утро, день дохода, вечер, воскресенье, 1-е число).
- Результат пишется в таблицу `insights` с ключом повтора, чтобы одна и та же подсказка не приходила дважды за период.
- Пороги (80%, «в 2 раза больше обычного», размер подушки, норма сбережений) — настройки пользователя со значениями по умолчанию.
- Строгость советника в настройках: мягкий (только важное), обычный, строгий (подсказывает чаще и жёстче).

## 5. API (первый этап)

Все ответы JSON, вход по токену Sanctum. Адреса на английском, тексты ошибок на языке пользователя.

```
POST   /api/auth/telegram/start            -> ссылка на бота и id запроса
GET    /api/auth/telegram/status/{id}      -> pending | approved + токен | used | denied | expired (заголовок X-Login-Secret)
POST   /api/auth/logout
GET    /api/me            PATCH /api/me    настройки, язык, советник
       /api/accounts                        CRUD
       /api/categories                      CRUD, стандартный набор создаётся при первом входе
       /api/transactions                    CRUD, фильтры: месяц, счёт, категория, тип, поиск
GET    /api/budgets?month=  PUT /api/budgets/{month}
       /api/income-schedules                CRUD
       /api/recurring-payments              CRUD, POST {id}/pay
       /api/tasks                           CRUD, POST {id}/complete
       /api/habits                          CRUD, PUT {id}/logs/{date}
GET    /api/today                           всё для экрана «Сегодня» одним запросом
GET    /api/rates?date=
POST   /api/advisor/can-afford              вердикт и объяснение
GET    /api/insights      POST /api/insights/{id}/feedback
POST   /telegram/webhook                    только с секретным заголовком Telegram
```

## 6. Вход через Telegram

1. Приложение просит у сервера запрос на вход и получает ссылку `t.me/<бот>?start=login_<одноразовый код>` и отдельный секрет, который знает только оно.
2. Пользователь нажимает ссылку, Telegram открывает бота, пользователь жмёт «Старт».
3. Бот проверяет, что Telegram ID есть в `ALLOWED_TELEGRAM_IDS`, и показывает сообщение «Вход в Компас, устройство: …» с кнопками «Войти» и «Отклонить». Нажать их может только тот, кто открыл ссылку. Код живёт 5 минут и используется один раз.
4. Приложение всё это время раз в 2 секунды спрашивает статус, предъявляя свой секрет. После «Войти» оно один раз получает токен Sanctum и сохраняет его (на телефоне в защищённом хранилище, шаг 1.8).
5. Новое устройство сначала просит придумать PIN, дальше спрашивает его при каждом запуске и после минуты в фоне. Пять неверных попыток выходят из аккаунта на этом устройстве. Отпечаток пальца появится вместе с Android-сборкой (шаг 1.8). Выход и смена PIN — в «Ещё».

Почему кнопка, а не вход сразу по «Старт»: иначе чужой человек мог бы начать вход у себя, прислать ссылку владельцу, и тот одним нажатием «Старт» впустил бы его в свой аккаунт. Секрет нужен по той же причине: ссылку видит Telegram, а токен забирает только приложение, которое начало вход.

Для разработки без бота есть `php artisan login:approve`: подтверждает последний ожидающий вход так же, как кнопка «Войти».

## 7. Экраны первого этапа

Нижнее меню: **Сегодня · Деньги · [+] · Дела · Ещё**. Вкладка «Цели» появится во втором этапе.

- **Вход**: кнопка «Войти через Telegram», затем установка PIN.
- **Сегодня**: дневной лимит, главные советы, привычки на сегодня, задачи, ближайшие платежи и доход.
- **Быстрая запись** (кнопка «+»): расход, доход или перевод; сумма, категория, счёт, дата; подсказка советника внизу.
- **Деньги**: месяц с бюджетами по категориям и отметкой темпа, список операций с фильтрами, счета и остатки.
- **Можно ли купить?**: сумма и категория, вердикт с объяснением.
- **Дела**: привычки (отметка одним касанием, серии) и задачи (сегодня, неделя, все).
- **Советы**: лента подсказок.
- **Ещё**: счета, категории, бюджет, дни дохода, регулярные платежи, советник, язык, тема, PIN, бот, выход.

## 8. Стандартные категории

Названия на узбекском — черновик, их нужно проверить. В скобках пометка для советника: О — обязательная, Г — гибкая.

**Расходы**

## 9. Бот в первом этапе

- `/start login_<код>` — вход (раздел 6). `/start` без кода — что умеет бот.
- Фраза с суммой создаёт расход: «такси 32к», «обед 85 000», «кофе 22000 налик», «$20 подписка». Сумма понимается в форматах `32к`, `32 000`, `1.5м`, `$20`, `20$`. Категория выбирается по словарю ключевых слов и по тому, куда раньше уходили такие фразы. Бот отвечает подтверждением и кнопками «Изменить категорию» и «Отменить».
- «+500к зарплата» — доход.
- «можно купить наушники 600к?» — вердикт советника.
- `/today` — лимит на сегодня, задачи, привычки.
- Утренняя сводка, предупреждения о бюджете, распределение дохода, вечернее напоминание.
- Отвечает только Telegram ID из списка разрешённых, остальным — вежливый отказ.

## 10. Риски и что проверить на хостинге

- **Анти-бот защита AHost** может отвечать страницей проверки вместо JSON на запросы приложения и на вебхук бота (так было в dealers). Нужен тикет в AHost с исключением `/api/*` и `/telegram/webhook` для нового поддомена.
- **Доступ к `cbu.uz` с хостинга** надо проверить командой из cPanel Terminal. Если закрыт, курс вводится руками, а всё остальное работает.
- **Сборка Android** требует Android SDK. Чтобы не ставить Android Studio, APK собирается в GitHub Actions и скачивается со страницы сборки.
- **Даты в SQLite и MariaDB** ведут себя по-разному (урок из steamkindergarten): сравнения дат только через `whereDate` или колонки типа `date`; CI проверяет на MariaDB.
- **Квоты AHost**: 2 ГБ диска и 125 000 файлов на все сайты аккаунта. Компас маленький, но релиз с `vendor` — около 10 000 файлов.
